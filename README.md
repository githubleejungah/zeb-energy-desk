# 제로에너지 단지 운영 데스크 (시제품)

가상의 제로에너지(ZEB) 아파트 단지 하나를 네 사람이 각자 화면으로 봅니다.

| 화면 | 누가 | 하는 일 |
|---|---|---|
| 시공사 콘솔 | 태양광 · 신재생 설비 시공사 | 안전 먼저 · 손실 큰 순 알람(지열 · 충전기는 시간으로), 출동 확정 · 보류 · 조치 입력, 출동 묶음 지도, 하자보증 · 사후관리 보고 · 연계 유지 기한, 구독 요금 |
| 입주민 앱 | 입주민 | 우리 집 1시간 사용량, 미션 참여 신청, 남는 전기 쓰기 미션 · 포인트, 판정 이의 |
| 단지 화면 | 건설사 · 관리주체(관리사무소) | 단지 시간별 합계, 공용 설비 현장 1차 확인, 제휴 리워드 예산 · 합계 리포트 |
| 본사 운영 어드민 | 서비스 회사 운영자 | 월 정산 마감 · 장애 감면, 본사 대기열 · 담당 지정 · 본사 조치, 예외 · 이관 결정 · 재심 판정, 감사 기록 |

- 데이터는 모두 가상입니다. 실제 회사 · 고객 · 가격이 아닙니다.
- 에너지 ICT 회사의 서비스 기획자 지원용 개인 프로젝트입니다. 문서 초안 · 코드는 Claude(AI)와 함께 만들었습니다.

## 실행법

빌드가 없습니다. `site/` 폴더를 정적 서버로 엽니다.

```
python -m http.server 8794 -d site
```

브라우저에서 `http://localhost:8794`를 엽니다. 위쪽 버튼으로 역할을 바꾸고, '1시간 · 1일 앞으로'로 시각을 넘깁니다.

시험(Node 22 이상):

```
node tools/run-tests.mjs      # 결과: tmp/test-results.json
node tools/secret_scan.mjs .  # 비밀값 검사
```

## 시연 순서(5분)

1. **시공사:** 안전 알람이 맨 위, 그다음 손실 큰 순. 통신이 끊긴 곳은 '추정'. 지도에서 출동 묶음(번호 = 들르는 순서)을 보고 **'출동 확정'**.
2. **본사 운영자:** 8월 정산 '마감'이 잠겨 있음(8월 말일까지 생긴 남은 일 8건). 예외 6건 판정 — 고르면 초안(감면 · 청구 변화를 숫자로 미리 봄), '확정'해야 반영 · 감사 기록 1줄(담당 없는 PV-32는 '이관 결정' 3갈래, 관리 종료는 한 번 더 확인), 본사 대기열 담당 지정(지정받은 시공사 화면에 보임). 감사 기록에 GEO-1 '자동 회복'(24시간 정상).
   - **건설사 · 관리주체:** 공용 설비 알람의 현장 1차 확인(체크리스트 → 해결 / 안 됨). 안전 알람은 '전문가만'.
   - **시공사:** 손실이 작은 알람은 '보류' — 14일 또는 보류 뒤 손실 3만 원이면 본사로.
3. **1시간 앞으로 × 4 → 시공사:** 안전 알람 '조치 입력' → **1일 앞으로** → 다음 날 정상 복귀로 종결.
4. **본사 운영자:** 새로 올라온 48시간 미확정 건 처리 → 마감 → 감면 확정이 감사 기록에.
5. **1일 앞으로 × 7:** 감사 기록에 '원본 삭제'(15분 원본). 입주민 판정 결과는 그대로, 9월 미션은 기준선용 1시간 합계(30일 보관)로 계속 판정.
6. **입주민 · 관리주체:** 1시간 합계만, 단지 합계만, 제휴사엔 5가지 합계만. 미션은 참여 신청한 세대만 판정(세대 고르기에서 H-0001을 고르면 '신청 전', '참여 신청'을 누르면 다음 미션부터).
