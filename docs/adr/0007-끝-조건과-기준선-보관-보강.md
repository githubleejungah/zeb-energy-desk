# 0007. 끝 조건 · 담당 · 기준선 보관 보강

- 상태: 채택 · 2026-11-25 (요구 Q18, 사용자 승인 "All as recommended")
- 근거: requirements Q18 · AC-69~79, 관찰 O3 · O4

## 결정

1. 사람이 손대야 끝나는 상태마다 기한을 둔다. 출동 확정 뒤 7일 조치가 없으면 본사로 1번 올린다. 기한 넘긴 작업 지시는 본사가 담당을 정하면 새 기한 7일을 준다.
2. 본사의 담당 지정은 알람에 `assignee`로 남겨 지정받은 시공사 화면에 보인다. 본사가 맡은 알람은 본사도 조치를 넣는다.
3. 이관 결정은 담당을 실제로 바꾼다: ① · ② → `END`(관리 종료, 일반 알람 0건), ③ → `PUB`(공공 기관, 일반 알람은 '기관 전달').
4. 저절로 회복된 고장은 24시간 이어서 정상이면 '자동 회복'으로 닫는다. 안전 알람과 작업 지시는 사람이 조치를 넣어야 닫힌다.
5. 미션 기준선은 15분 원본이 아니라 기준선용 1시간 합계에서 읽는다. 1시간 합계는 판정 시각 앞 30일까지만 읽힌다.
6. 미션은 참여 신청한 세대만 판정한다.
7. 지열 · 충전기는 손실을 원으로 매기지 않고 시간으로 보여 주며, 정렬은 안전 → 금액 있는 알람 → 금액 없는 알람 순이다.

## 이유

- 독립 검토에서 끝나지 않는 상태 3곳(작업 지시 반복 올림 · 출동 확정 방치 · 이관 뒤 본사 복귀)을 재현했다.
- 15분 원본을 7일 뒤 지우면 다음 달 미션이 모두 판정 불가가 됐다(재현: 9/8 미션 300세대 판정 불가).
- 신청 없이 판정하면 반응하지 않은 세대의 우연 성공이 성공의 약 13%였다(O4). 제휴사 돈이 반응 없는 세대에 나간다.
- 지열 · 충전기의 원 단위 손실은 근거가 없다(태양광은 이웃 비교 · 단가가 있음).

## 대안

- 자동 회복 없이 지금대로(사람이 원인을 넣어야 끝) — 본사 일이 쌓여 기각.
- '확인 필요' 상태로 두고 본사로 안 올림 — 끝 조건이 없어 기각.
- 옵트인 대신 리포트 이름만 '판정 대상 세대'로 — 돈이 새는 문제가 남아 기각.
- 15분 원본 보관을 30일로 늘림 — 개인정보 최소화 원칙(AC-47)과 맞지 않아 기각.

## 결과

- 시연 상태(9/1 09:00)의 8월 마감 잠금 사유가 '8월 말일까지 생긴 것'으로 줄어든다.
- 기준선용 1시간 합계라는 보관 데이터가 하나 늘었다(data-model 1절, architecture 4-4절 ②).
- 숫자(7일 · 24시간 · 신청 비율)는 가정 AS-13 · AS-14로 남긴다.
