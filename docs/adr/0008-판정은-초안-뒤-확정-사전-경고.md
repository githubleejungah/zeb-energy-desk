# 0008. 판정은 초안 뒤 확정 · 사전 경고는 6가지 행동에만

- 상태: 채택 · 2026-11-25 (요구 Q19, 사용자 "추천안대로 할게요" · 수정안 승인 "Approve as is")
- 근거: requirements Q19 · AC-80~90

## 결정

1. 감사 기록은 고치거나 지우지 않는다(AC-34). 대신 실수가 기록되기 전에 막는다.
2. 예외 · 재심 판정은 '초안 → 확정' 2단계로 한다. 초안은 다시 고를 수 있고, 감사 기록 0줄 · 계산 반영 0건이다. 확정할 때 1줄을 남기고 초안을 고른 횟수를 함께 적는다.
3. 사전 경고는 돈 · 담당이 바뀌는 6가지 행동(판정 · 관리 종료 · 담당 지정 · 본사 직접 · 예산 승인 · 마감)에만 둔다. 경고 내용은 '바뀌는 금액 · 건수'이고, 근거 없는 기준값(몇 배 · 몇 %)을 두지 않는다.
4. 계산은 `core/warnings.js` 한곳에 둔다.

## 대안

- 정정 기록(원래 줄을 두고 반대 줄을 덧붙임) — 실수가 생긴 뒤 처리라 검토 시간이 남는다. 제품화 때 함께 쓸 수 있으나 시제품에서는 초안 단계로 먼저 줄인다.
- 되돌리기 유예 시간 — 초안과 겹치고, 기다리는 사이 다른 사람이 끝난 일로 알 수 있으며, 시연 시계가 1시간 단위라 보여 주기 어려워 뺐다.
- 모든 행동에 경고 — 경고 피로로 읽지 않고 넘기게 되어 뺐다.
- 해시 사슬 · 덮어쓰기 불가 저장소 · 보관 기간 · 이상 징후 알림 · 표본 검토 — 서버가 필요해 입사 후 로드맵 1번에 둔다.

## 결과

- 확정 안 한 초안은 '미판정 예외' · '재심 대기'로 마감을 잠가 끝없이 남지 않는다(AC-32).
- 초안을 여러 번 바꾼 사실은 확정 줄의 횟수로만 남는다. 무엇에서 무엇으로 바꿨는지는 남지 않는다(시연 범위).
