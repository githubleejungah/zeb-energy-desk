# 데이터 설계

> 상태: 승인 · 구현에 맞춰 고침(2026-11-24) · 근거: [requirements.md](requirements.md) · [architecture.md](architecture.md)
> 데이터는 모두 가상이다. 사람은 가명 ID로만 부른다(AC-51).

## 1. 정본 표

| 데이터 | 정본 | 주인(바꿀 수 있는 쪽) | 사본 |
|---|---|---|---|
| 단지 · 동 · 설비 · 세대 · 시공사 · 계약 · 요금제 (기준 데이터) | `site/js/data/seed.js` | 본사(시연에서는 파일 고정) | 역할별 화면 데이터(걸러 낸 것) |

| 세대 사용량 15분 원본 | `raw.js`의 세대 생성 함수 + 씨앗값 (**저장 안 함**) | 없음(생성 전용), 읽기는 정산 모듈만 | 없음 |
| 세대 사용량 1시간 합계 | 정산 모듈이 원본에서 만든 값 | 정산 모듈 | 입주민 본인 화면 |
| 단지 합계(발전 · 공용 사용) | 정산 모듈이 만든 값 | 정산 모듈 | 관리주체 · 본사 · 입주민 화면 |
| 사람 행동(출동 확정 · 조치 결과 · 확인 표시 · 보류 · 현장 1차 확인) | localStorage `zed:v1:state` 의 `dispatches` · `results` · `seen` · `holds` · `siteChecks` | 시공사(출동 · 조치 · 보류), 관리주체(1차 확인), 본사(담당 지정) | — |
| 담당 이관 결정 | `zed:v1:state` 의 `ownerOverrides` | 본사(예외 판정) | 정산(공공 기관 배정 설비는 청구 안 함) |
| 알람 · 작업 지시 | 저장 안 함. 설비 계측 + 사람 행동으로 매번 계산(ADR 0006) | 규칙(alarms.js) | 시공사 · 본사 화면, 관리주체(안전 알람만) |
| 의무 기록(보고서 초안 · 제출 기록) | `zed:v1:state` 의 `reports` | 시공사 | 시공사 · 본사 화면 |
| 예외 | `zed:v1:state` 의 `exceptions` | 본사(판정) | 본사 화면 |
| 월 정산 결과 | `zed:v1:state` 의 `settlements` | 본사(마감) | 본사 화면, 시공사(자기 청구액만) |
| 미션 판정 기록 | `zed:v1:state` 의 `missionLog`(날짜별: 세대 가명 → 판정 · 포인트 · 기준선 대비 % · 빈 칸 수. 사용량 값 없음) | 정산 모듈(처음 판정 때 한 번 기록, 다시 계산 안 함) | 입주민(자기 것만), 관리주체 · 제휴사 리포트(합계만), 본사(재심 대상만) |
| 이의 · 재심 | `zed:v1:state` 의 `appeals` | 입주민(제기) · 본사(판정) | 입주민(자기 것), 본사 |
| 제휴 예산 | `zed:v1:state` 의 `budgets` | 관리주체(승인) | 관리주체 · 본사 화면, 제휴사 리포트 |

| 시연 시각 | `zed:v1:state` 의 `clock` | 보는 사람('앞으로' 버튼) | 모든 규칙 입력 |

## 2. 구조

### 2-1. 기준 데이터 (seed.js)

| 묶음 | 칸 | 예(가상) | 민감도 |
|---|---|---|---|
| `complex` 단지 | id · 이름 · 세대 수 · 동 목록 · 구역 | `C1` · '가상 제로에너지 단지' · 300 · 6개 동 · Z1 | 내부 |
| `assets` 설비 | id · 종류(`pv` 태양광 · `geo` 지열 · `ev` 충전기) · 용량 kW · 위치(배치도 좌표) · 구역 · 소유 구분(`common` 단지 공용 · `house` 단독주택) · 설치일 · 담당 시공사 id · 보증 만료일 · 연계 유지 만료일 | `A-101` · pv · 30 · (420,62) · Z1 · common | 내부 |
| `households` 세대 | 가명 id · 동 | `H-0412` · 101동 | 기밀(사용량과 이어지면) |
| `contractors` 시공사 | id · 이름(가상) · 요금제 · 계약 기간 | `K1` · '가상 시공사 1' · `pro` | 내부 |
| `plans` 요금제 | id · 개소당 월 요금(가상) | `pro` · `ops` | 내부 |
| `partners` 제휴사 | id · 이름(가상) | `P1` · '가상 충전사업자' | 내부 |
| `config` 설정값 | 알람 · 정산 · 미션 숫자 전부(AS-6 · 7 · 10) | 3시간 · 50% · 4시간/10% … | 내부 |

- 숫자 설정값은 `config` 한곳에만 둔다. 규칙 코드에 숫자를 직접 쓰지 않는다(잔여 위험 R-4).
- 세대에는 이름 · 전화 · 주소 칸이 **없다**. 동 · 호와 가명을 잇는 표도 만들지 않는다(Q6-5).

### 2-2. 상태 (localStorage `zed:v1:state`)

```text
{
  version: 1,
  clockH: 753,                          // 시연 시각(2026-08-01 00:00부터 센 시간). 753 = 2026-09-01 09:00
  dispatches: [{ id, contractorId, by, alarmKeys[], proposedH, confirmedH }],   // 출동 확정 · 본사 담당 지정
  results:    [{ alarmKey, atH, memo }],                                        // 조치 결과(메모는 500자, 글자로만)
  seen:       { "PV-03:low": 753 },                                             // '확인' 표시(종결 아님)
  holds:      [{ alarmKey, atH, by }],                                          // 보류(다음 정기 방문, AC-64)
  siteChecks: [{ alarmKey, atH, result: "solved"|"failed", items[] }],          // 관리주체 현장 1차 확인(AC-60~62)
  ownerOverrides: { "PV-32": { to: "PUB", atH } },                              // 이관 결정 '공공 기관 배정'(AC-67)
  reports:    [{ assetId, year, submittedH }],
  budgets:    [{ partnerId, approvedWon, approvedH }],
  appeals:    [{ missionDay, householdId, filedH, decision, decidedH }],
  exceptionDecisions: { "OC-SO-3": { decision: "company", decidedH } },
  settlements: { "2026-08": { month, closedH, lines[], totalFeeWon, totalCreditWon, totalBilledWon } },
  missionLog:  { "20": { day, hour, publishedH, appealDueH, movedKwh, results: { "H-0002": { verdict, points, ratioPct, blanks } } } }
}
```

- 상태 값 이름(`status` 등)은 [flows.md](flows.md)의 상태 기계와 같다.
- `missionLog`에는 판정 · 포인트 · 기준선 대비 % · 빈 칸 수만 있고 사용량 값은 없다(AC-35 · Q6-4). 한 번 기록한 판정은 다시 계산하지 않아, 원본을 지운 뒤에도 공개한 결과가 바뀌지 않는다.
- 형식 버전이 1이 아니거나 읽을 수 없으면 기본 상태로 되돌린다(AC-52).

### 2-3. 감사 기록 (localStorage `zed:v1:audit`)

```text
[{ seq, at, role, action, target, rule }]
// 예: { seq: 12, at: "2026-09-01T10:00", role: "hq", action: "settlement.close", target: "2026-08", rule: "AC-32 잠금 0건" }
```

- 행동 종류: 정산 마감 · 감면 확정 · 예외 판정 · 보고서 제출 · 담당 변경 · 예산 승인 · 원본 삭제 · 시연 초기화(AC-34 · AC-47 · AC-53).
- `target`에는 ID만 넣는다. 사용량 값 · 이름 · 연락처는 넣지 않는다(AC-35).
- `audit.js`에는 덧붙이는 함수만 있다. 고치기 · 지우기 함수는 0개(AC-34).

### 2-4. 15분 원본 (저장 안 함)

- `raw.householdUsage(householdId, day)` → 그날 96칸(kWh). 씨앗값 = 세대 id + 날짜 → 같은 입력이면 같은 값.
- 일부러 빈 칸을 섞는다(판정 불가 사례, AC-39).
- 삭제 대상 달은 호출하면 '삭제됨' 오류를 돌려준다(AC-47).
- 이 함수를 불러 쓰는 파일은 `settlement.js` 하나다(시험으로 검사, SEC-08).

## 3-1. 신원 정보 (AC-68 · Q17)

- 시제품: 세대는 가명 ID(`H-0001` 형식)뿐이다. 이름 · 연락처 · 동 · 호수 칸과 가명 ↔ 실제 세대 연결표를 두지 않는다.
- 제품화 때: 신원 금고 · 사용량 저장소 · 정산 기록을 나눠 둔다(architecture.md 4-4절). 사용량 쪽 위치 정보는 단지 ID까지만.
